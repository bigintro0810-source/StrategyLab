# 形状判定版 三角保ち合い(可変タッチ・回帰直線方式) 仕様書 v2

対象関数(予定): `ascending_triangle_shape` / `descending_triangle_shape`(既存実装を全面的に置き換える)

**注記: これは現行実装(`docs/pattern_spec_channel_patterns_shape.md`、4点固定・
共通チャネルコア方式)を置き換える新設計。旧実装は`ascending_triangle_shape_legacy`
/`descending_triangle_shape_legacy`として温存する(ボックスと同じ方針)。
ウェッジ/ペナント/フラッグは対象外(引き続き旧共通コアを使用)。**

`docs/pattern_spec_ascending_box_shape_v2.md`(ボックスv2)がベース。共通する
部分(3状態モデル・先読み防止・min_touch_gap_bars・孤立度チェック等)は
説明を簡略化し、差分を中心に記す。

---

## 1. ボックスv2との違い

ボックスは上下とも「水平線+極値+取り消し」だったが、三角保ち合いは
**斜めの支持線/抵抗線**を持つため、片方(斜めの線)は水準ではなく
**回帰直線**で表現する。

| | 上昇三角保ち合い | 下降三角保ち合い |
|---|---|---|
| 下値の線 | 上昇(回帰直線、3点固定) | 水平(極値+取り消し、ボックス方式) |
| 上値の線 | 水平(極値+取り消し、ボックス方式) | 下降(回帰直線、3点固定) |
| ブレイク方向 | 上 | 下 |

以下「回帰側」「水平側」という呼び方で統一する(上昇なら回帰側=下値、
水平側=上値。下降なら逆)。

## 2. 点1の探索方向(2方向、2026-08-18追加)

ボックスは山(高値)からしか探索しなかったが(旧仕様の既知の限界1)、
三角保ち合いは**回帰側・水平側どちらからでも点1を探索し、両方の結果を
マージする**。

- **回帰側起点**: 点1=回帰側の1点目(谷1相当)。まず回帰側の点を先に集め
  始める。
- **水平側起点**: 点1=水平側の1点目(上1相当)。まず水平側の点を先に
  集め始める。

理論上は同じ形が両方から見つかるはずだが、ボックスで確認された「起点の
型によって値動きの決着方向に非対称性がある」実データ上の性質(docs/
pattern_spec_channel_patterns_shape.md §4.1)がある可能性を考慮し、
取りこぼしを防ぐために両方向を実装する。同じ形が両方向から重複して
見つかった場合の重複排除は行わない(ボックス/トリプル/H&Sと同じ、複数の
独立した点1候補が重なるケースの扱いを踏襲 - 既知の限界として許容)。

---

## 3. 構成点

最小構成が揃うまでは**山谷交互を強制する**(2026-08-19、ユーザー指示)。
点1と逆の型から交互に探索し、点1の型によって最小構成の点数が変わる:

- **回帰側起点(谷始まり)**: 谷1・山1・谷2・山2・谷3 の順(回帰側3点・
  水平側2点、計5点)。回帰側は3点集まった時点で最小二乗法により1本の
  直線に当てはめる(§5)。
- **水平側起点(山始まり)**: 山1・谷1・山2・谷2・山3・谷3 の順(回帰側
  3点・水平側3点、計6点)。回帰側が3点必要という制約と、交互という制約を
  両方満たすには、水平側も自然に3点必要になる(山始まりで奇数長の交互
  列を回帰側=3で終えるには、水平側も3点必要という帰結)。

回帰側3点それぞれ・水平側の各点は両側確認ピボット(交互の順で1つずつ
交互に探す)。最小構成が揃った**後**に追加される点(回帰側4点目以降・
水平側3点目以降)は左側のみ確認で、交互の強制はしない(§4・§5参照 -
どちらの側にタッチが増えても構わない)。

個々の点の選び方(窓内でどれを採用するか)はボックス/旧チャネル共通コアと
同じ「より極端な値のときだけ更新」(extreme-wins)方式。

## 4. 水平側(極値+取り消し)

ボックスの§4と完全に同じ(山最高値/谷最安値を基準に、許容誤差
`(上値抵抗線の価格 − 下値支持線の価格) × level_tolerance_mult`の範囲外に
出た既存点を取り消し)。ただし高さの計算(§6)がボックスと異なる点に注意
(下値がボックスのような固定値ではなく回帰直線の値になる)。

### 4.1 回帰直線が確定/引き直された時点の遡及チェック(2026-08-19追加)

回帰直線がまだ確定していない間は、高さの基準が無いため水平側タッチを
無条件で採用している(§5.2参照)。そのため、回帰直線が**新しく確定/
引き直された瞬間**に、その時点までに採用済みの水平側タッチすべてを、
新しい直線を基準に改めてチェックする:

```
各点について: line_at(その点のバー) = 新しい回帰直線の値
許容誤差 = |水平側極値 − line_at(その点のバー)| × level_tolerance_mult
採用条件: 上昇三角保ち合いなら 価格 >= 水平側極値 − 許容誤差
          下降三角保ち合いなら 価格 <= 水平側極値 + 許容誤差
```

**実装時の注意(2026-08-19、実データ検証で発見・修正)**: 当初この判定式を
「価格が直線の値からどれだけ離れているか」(`|価格 − line_at| <= 許容誤差`)
という対称な式で書いてしまい、水平側極値そのものの点(定義上、直線からの
高さがそのまま基準になる点)まで誤って弾いてしまう不具合があった。正しくは
§4本文・ボックスの取り消しロジックと同じ「水平側極値からどれだけ離れて
いるか」という向き付きの式(`価格 >= 極値 − 許容誤差`)を使う必要がある。
この式なら極値そのものの点は必ず条件を満たす。

### 4.2 山谷交互の維持(2026-08-19追加)

§2の通り探索そのものはターン単位で山谷交互を強制しているが、確定済みの
点を後から取り消す処理(この§4.1の遡及チェック、および回帰直線引き直し
時の§5.2手順3)は、それぞれ**自分の側の点だけ**を条件で絞り込むため、
片方の側だけで点が削られると、残った点を時刻順に並べたときに同じ種類が
連続してしまうことがある(ユーザー報告「交互になってない」の実例で発覚
- 谷谷山山谷のような並びが実際に混入していた)。

このため、水平側の取り消し(§4.1)・回帰直線の引き直し(§5.2手順3)いずれ
でも、削除後の回帰側+水平側を時刻順にマージした結果が実際に山谷交互に
なっているかを直接チェックする。交互にならない場合:
- 回帰直線の引き直し中(§5.2手順2の組み合わせ探索)なら、その組み合わせ
  を不採用にして次の組み合わせを試す(他の組み合わせなら交互を保てる
  可能性があるため)。
- 水平側の取り消し(§4.1、極値更新による退避)なら、退避そのものを確定
  させず、直前までの交互な状態を保ったまま§5.2手順4と同じ扱いで打ち切る
  (退避は価格が実際にその極値を更新したという事実に基づく一回限りの
  判定のため、他の候補を試す余地がない)。

### 4.3 タッチ数上限(MAXT)到達時の引き直しバグ(2026-08-19発見・修正)

回帰側候補プール(reg_all、最大`_ASC_BOX_MAX_TOUCHES`=40点)が満杯の状態で
新しい候補が来ると、その候補はプールに保存されない(保存領域が無いため)。
このとき、直線引き直しの遡及フィルタ(§5.2手順3)が誤って「プールの
末尾(=満杯になる前の古い40番目の点)」を無条件採用し、実際に直線を
成立させた本人である**今回の候補**を採用し忘れる不具合があった。プールの
古い40番目の点は新しい直線に必ずしも沿っていないため、許容誤差から明らか
に外れた点が構成点として表示される原因になっていた(ユーザー報告「下値
支持線が許容誤差から外れて見える」)。

修正: 遡及フィルタは起点・末尾を位置で無条件採用せず、プール内の全点を
同じ許容誤差判定にかける(起点・組み合わせに使った点は判定式自体が採用
条件と同一のため必ず通る)。加えて、今回の候補がプール満杯で保存されて
いない場合は、判定を通過済みの候補自身を明示的に追加する。

## 5. 回帰側(回帰直線+引き直し)

### 5.0 全体方針(2026-08-18、設計変更)

当初は「回帰側1・2・3点目が決まった時点で1回だけ最小二乗法を計算し、
以降固定」という設計だったが、これをやめた。**起点(点1)だけは常に固定**
するが、それ以外の2点は「起点+既存の点のいずれか1つ+新しい候補」の
組み合わせの中から、条件(§5.1〜5.3)をすべて満たすものが見つかるたびに
**都度引き直せる**。

### 5.1 回帰直線の計算

3点(起点+既存の点1つ+新しい候補)から最小二乗法で1本の直線を求める:

```
slope = (3×Σ(bar×price) − Σbar×Σprice) / (3×Σ(bar²) − (Σbar)²)
intercept = (Σprice − slope×Σbar) / 3
line_at(bar) = slope × bar + intercept
```

### 5.2 新しい候補が出るたびの判定

回帰側の新しい候補(最小構成が揃うまでは両側確認、揃った後は左側のみ
確認)が出るたびに:

1. **既に回帰直線が成立している場合**、まずその候補が**現在の直線**に
   合うか確認する: `許容誤差 = |水平側極値 − line_at(候補バー)| ×
   level_tolerance_mult`、`|候補価格 − line_at(候補バー)| <= 許容誤差`
   を満たせば、直線は動かさずそのまま追加採用(表示対象に加える)。
2. **合わない場合(または、まだ一度も直線が成立していない場合)**、
   「起点 + これまでに採用されたことがある点のいずれか1つ(古い順) +
   今回の候補」という3点の組み合わせを順に試す。各組み合わせについて
   §5.1で直線を引き、以下をすべて満たす**最初の**組み合わせを新しい
   回帰直線として採用する:
   - 傾きの向きが正しい(上昇三角保ち合いならプラス、下降ならマイナス)
   - 3点それぞれが、その直線から許容誤差(§5.2の1と同じ式)以内
   - §5.3の急さ(ATR倍率)の条件を満たす
   - §5.4の遡及破綻チェックを満たす(起点〜今回の候補までの生の高値・
     安値がこの直線を大きく割り込んでいない)
3. 新しい直線が採用されたら、これまでに一度でも採用されたことがある
   点**すべて**(起点・今回の候補は無条件に含む)を、新しい直線の許容
   誤差で改めて絞り込み、それが以降の表示・本数となる(ボックスの取り
   消しと同じ考え方を回帰側にも適用したもの)。
4. どの組み合わせも条件を満たさない場合:
   - 既に一度でも回帰直線が成立していた(Candidateが出せる状態だった)
     なら、**窓内破綻判定と同じ扱いでパターン全体をInvalidated**にする。
   - まだ一度も直線が成立していなければ、罰則なし(単に「まだ形になって
     いない」として探索を続ける)。

不採用になった候補自体が確定ピボットであれば、それは§2の「点1候補ごとに
独立探索」の枠組みの中で、いずれ**別の探索の点1として自動的に**試される
(このチェーンの中で救済する特別な仕組みは持たない)。

### 5.3 急さ(ATR倍率)の下限/上限(2026-08-18追加)

最小二乗法は3点の当てはまりが良くても、全体の値幅が小さい(=ほぼ水平に
近い、教科書的には「上昇」と呼べない)直線でも数式上は成立してしまう。
これを防ぐため、直線の起点(3点のうち最も古いバー)から終点(最も新しい
バー)までの、直線上の値幅を、候補バー時点のATRで正規化してチェックする:

```
急さ = |slope × (終点バー − 起点バー)|
下限 = ATR(14)[候補バー] × min_slope_rise_atr_mult(既定1.0)
上限 = ATR(14)[候補バー] × max_slope_rise_atr_mult(既定0.0=無制限)
採用条件: 下限 <= 急さ <= 上限
```

この条件も、直線を新しく採用する判定(§5.2手順2)の一部として毎回
チェックする。
(この候補チェーンの中で救済する特別な仕組みは持たない)。

### 5.4 直線確定前の区間に対する遡及破綻チェック(2026-08-19追加)

§5.2手順2の当てはまりチェック(起点・xi・候補の3点)は、その3点自身が
直線に沿っているかしか見ておらず、**その3点の間にある他の生の値動き**は
見ていない。また§6の順方向の逸脱判定は直線が確定した**後**にしか動かない
ため、直線がまだ確定していない間(起点〜確定までの区間)に生の高値・
安値がこの直線を大きく割り込んでいても、従来はどちらのチェックにも
引っかからず見過ごされていた(ユーザー報告「下値抵抗線が大幅に割れてる
のに無効にならない」)。

このため、直線を新しく採用する判定(§5.2手順2)に、起点〜今回の候補
までの区間を生の高値・安値で§6と同じ式でチェックする手順を追加した:

```
各バーkについて(起点 <= k <= 今回の候補バー):
line_at(k) = 候補中の直線の値
高さ = |水平側極値 − line_at(k)|
バッファ = 高さ × breakout_buffer_mult
上昇三角保ち合いなら: 安値[k] < line_at(k) − バッファ を1つでも満たせば不採用
下降三角保ち合いなら: 高値[k] > line_at(k) + バッファ を1つでも満たせば不採用
```

不採用になったらこの組み合わせ(xi)は使わず、§5.2手順2の「次の組み合わせ
を試す」処理にそのまま合流する。どの組み合わせも遡及破綻チェックを含めて
満たせなければ、§5.2手順4と同じ扱い(既に直線が確定していればInvalidated、
まだなら罰則なしで探索継続)になる。

水平側(§4)の遡及チェックは対象にしていない(この問題は回帰側の直線が
まだ確定していない間に特有のギャップであり、水平側は既に§4.1で遡及
チェックを持っている)。

## 6. ブレイク・逸脱判定

ボックス§5・§6とほぼ同じだが、高さと「線の値」の扱いが違う:

```
height_at(j) = 水平側極値 − line_at(j)   (上昇三角保ち合いの場合。下降は符号反転)
tol_at(j) = height_at(j) × level_tolerance_mult
buf_at(j) = height_at(j) × breakout_buffer_mult
```

- 上抜け(水平側+buf_at超え、終値/ヒゲは`breakout_type`次第)→Confirmed
  (最小構成が揃っている場合のみ、揃っていなければInvalidated)。
- 下抜け(回帰直線line_at(j)−buf_at割れ)→Invalidated。
- 逸脱・ブレイクの継続的チェックは、回帰直線が確定(回帰側3点)かつ
  水平側極値が1点以上ある状態になってから開始する(ボックスの
  `have_height`と同じ考え方)。

### 6.1 ブレイク時の収束チェック(2026-08-19追加)

上抜けブレイクが成立(§6の上抜け条件を満たす)しても、三角保ち合いとして
本当に収束しているかを別途チェックできる。谷1(起点、実際の価格)から
上値抵抗線までの値幅と、ブレイクしたバーでの回帰直線の延長(line_at)から
上値抵抗線までの値幅(height_at、上のブレイク判定で計算済みの値と同じ式)
を比較する:

```
height_start = |水平側極値 − 谷1(起点)の実際の価格|
比率 = height_at(ブレイクバー) / height_start
採用条件(max_breakout_height_ratio > 0の時のみ): 比率 <= max_breakout_height_ratio
```

満たさない場合はブレイクによるConfirmedを不採用にする(§6の終値/ヒゲ
確認と同じ扱い - 最小構成が揃っていればInvalidated、揃っていなければ
そのままInvalidated)。`max_breakout_height_ratio`が0以下(既定)なら
このチェックは無効。

## 7. パラメータ

ボックスからの変更点のみ記す(それ以外はボックスと同じ意味・同じ既定値):

| パラメータ | 既定値 | 意味 |
|---|---|---|
| `pivot_left_bars` | 3 | ピボット左本数 |
| `pivot_right_bars` | 3 | ピボット右本数(最小構成の点にのみ使用) |
| `min_touch_gap_bars` | 5 | 同方向タッチ同士の最低間隔(ボックスと同じ) |
| `level_tolerance_mult` | 0.15 | 水平側の採用条件・回帰側の許容誤差(共通、ボックスと同じ既定値) |
| `breakout_buffer_mult` | 0.05 | ブレイク判定余白 |
| `breakout_type` | `close` | ブレイク判定基準(`close`/`wick`) |
| `max_box_bars` | 500 | 点1からの最大本数(タイムアウト、ボックスと同じ既定値) |
| `pivot_spike_window_ratio` | 0.0(2026-08-19に0.5から変更) | 孤立度チェックの窓(本数の倍率、0で窓なし=実質無効) |
| `pivot_spike_excess_atr_max` | 0.0(無効、2026-08-19に1.3から変更) | 孤立度チェックの突出許容(0以下で無効) |
| `min_slope_rise_atr_mult` | 1.0 | 回帰直線の急さ下限(ATR倍率、§5.3、2026-08-18追加) |
| `max_slope_rise_atr_mult` | 0.0(無制限) | 回帰直線の急さ上限(ATR倍率、§5.3、2026-08-18追加) |
| `max_breakout_height_ratio` | 0.0(無効) | ブレイク時の収束チェックの比率上限(§6.1、2026-08-19追加) |

**削除するもの**(旧実装から): カウフマン効率比(`efficiency_ratio_*`)、
トレンドライン乖離(`trendline_dev_pct*`)、`symmetry_ratio_min/max`
(本数を直前区間の倍率で決める窓)、`breakout_deadline_min_bars`/
`breakout_deadline_ratio_max`(ブレイク期限を別立てにする仕組み -
`max_box_bars`のタイムアウトに統一)、`converge_margin`/`width_tol`
(収束/平行判定 - この2家系では使わない)、`top_tolerance_mult`という
名前は`level_tolerance_mult`に統一(ボックスと同じ命名)。

**残すもの**: 孤立度チェック(`pivot_spike_*`、本数の倍率窓のまま例外的に
残す、2026-08-18ユーザー確定)。

## 9. 検証手順
