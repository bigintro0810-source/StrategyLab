## 1. 用語・ポイント定義

時間順(古い → 新しい)で、パターン本体の3ポイントを次のように定義する。

| 記号 | Double Top | Double Bottom | 参考元での位置 |
|---|---|---|---|
| P1 | 第1山 | 第1谷 | ZigZag配列 index 3 |
| P2 | ネック(谷) | ネック(山) | ZigZag配列 index 2 |
| P3 | 第2山 | 第2谷 | ZigZag配列 index 1 |
| P0 | P3の後に発生した最新の反対方向スイング | 同左 | ZigZag配列 index 0 |

P0は形状計算には使わないが、**存在自体がCandidate成立の前提**になる(判定が
index 1〜3を読むため、P3がindex 1へ移動して初めて評価対象になる)。

## 2. パラメータ

| 内部名 | UI表示 | 型 | 初期値 | 最小 | 最大 | step | 意味 |
|---|---|---|---|---|---|---|---|
| `length` | ZigZag期間 | int | 10 | 5 | 制限なし | 5 | 本。Pivot候補のlookback長 |
| `max_risk_ratio` | 最大リスク比率 | float | 30 | 5 | 100 | 5 | %。5章のratioの上限(**厳密に「未満」**) |

**閾値演算子の注意**: `max_risk_ratio` は「以下」ではなく厳密な「未満」。
計算値がちょうど30.0で設定値が30なら**不採用**。

**有効範囲の保証(v2.1)**: 上表の最小・最大は**検出器の内部でも保証する**。UI側の
min/max指定だけに頼らない — 保存済みJSONの読み込みなど、UIを介さずに検出関数へ
直接値が渡される経路があるため。範囲外の値は境界値へ丸めてから計算する。

```
length         : 5未満なら5にする(上限なし)
max_risk_ratio : 5未満なら5、100超なら100にする
```

**stepの扱い**: `step` は**UI入力欄の増減単位としてのみ**扱う。検出器は上記の範囲内
であれば刻みに乗らない値(例: `length=7`、`max_risk_ratio=33.5`)もそのまま受け付ける。
自動探索が試す候補値は刻みに合わせて用意するが、これも制約ではなく候補の選び方の
問題として扱う。

参考元にある表示専用パラメータ(`showZigzag` / `showPivots` / `showStats` /
各種色 / `DisplayRiskPerReward`)は検出結果に一切影響しないため、この検出器には
含めない(StrategyXではチャート描画側の責務)。

## 4. Pivot / ZigZag 仕様

### 4.1 Pivot候補(左右対称ではない、lookback型)

各バー `i` で、現在バーが**直近 `length` 本(自分を含む)** の最高値/最安値そのものか
を判定する。右側の確認を待たない。

```
ph_valid(i) : high[i] == max(high[i-length+1 .. i])
pl_valid(i) : low[i]  == min(low[i-length+1 .. i])
```

窓が満たない先頭 `length-1` 本は判定しない(参考元の `highestbars` がna)。

同値(タイ)の扱い: 参考元の `highestbars` は最も新しい位置のオフセットを返すため、
過去バーと同値でも現在バーがPivot候補になる。上式の `==` がこれと一致する。

### 4.2 方向 `dir`

| ケース | dir |
|---|---|
| ph_validのみ成立 | +1 |
| pl_validのみ成立 | -1 |
| 両方成立 | 前バーのdirを維持 |
| どちらも不成立 | 前バーのdirを維持 |

初期値は 0。`dirchanged` は「前バーのdirから変化したか」。

### 4.3 ZigZag配列の追加・置換

配列は最新ポイントを先頭(index 0)に保持する。`ph_valid or pl_valid` のバーでのみ
更新する。追加する値は `dir == +1 なら high[i]、それ以外なら low[i]`。

| 条件 | 動作 |
|---|---|
| 配列が空、または dirが変化した | **新規追加**(先頭へunshift) |
| 同方向で、より極端な値(dir=+1で `値 > 現index0`、dir=-1で `値 < 現index0`) | **index 0を置換**(先頭を除去してから新規追加) |
| 同方向だが極値を更新していない | 配列変更なし |
| 配列サイズが10を超えた | 最古(末尾)を削除 |

### 4.4 HH / LH / HL / LL 分類

追加/置換のたびに、**ひとつ前の同方向Pivot**と比較して内部符号を決める。

```
mult = 2 if (dir * 新値 > dir * ひとつ前の同方向Pivotの値) else 1
内部符号 = dir * mult
```

| 内部符号 | 名称 | 判定 |
|---|---|---|
| +2 | HH | 新High > 直前の同方向High |
| +1 | LH | 新High <= 直前の同方向High |
| -2 | LL | 新Low < 直前の同方向Low |
| -1 | HL | 新Low >= 直前の同方向Low |

**比較対象の位置**(重要):
- 新規追加のとき: 挿入**前**の index 1(直前のindex 0は反対方向なので、index 1が
  ひとつ前の同方向Pivot)
- 置換のとき: 先頭を除去した**後**の index 1(= 除去前の index 2)

どちらも「ひとつ前の同方向Pivot」を指す。比較演算子は厳密な `>` なので、
**完全同値はHH/LLではなくLH/HLに分類される**。

**配列サイズが2未満のときは常に mult = 1**(比較対象が存在しないため)。系列内で
最初に現れるPivotは、たとえ実際には新高値でもLH(またはHL)扱いになる。

### 4.5 dir = 0 のまま追加されるケース

系列の先頭で ph_valid と pl_valid が同時成立すると、dirが0のまま
`値 = low[i]`、内部符号 = 0 で追加される。符号0は5章のどの条件にも一致しないため
パターンには参加できず、そのまま配列から押し出される。参考元の挙動をそのまま
再現する。

## 5. Candidate(候補)判定

配列サイズが**4以上**のときのみ評価する。index 1 / 2 / 3 を P3 / P2 / P1 として読む。

### 5.1 価格形状フィルター

```
risk   = |P3価格 - P1価格|
reward = |P3価格 - P2価格|
ratio  = risk × 100 / (risk + reward)
成立条件: ratio < max_risk_ratio
```

**名称上の注意**: 参考元では `riskPerReward` と呼ばれるが、一般的な risk/reward比
ではなく `risk / (risk + reward) × 100` の百分率である。計算式を正とし、名称から
意味を推定しない。

**ゼロ除算**: `risk + reward == 0`(3点が完全同値)のとき、参考元では ratio が na に
なり `na < max_risk_ratio` は偽。したがって **Candidateは成立しない**。

### 5.2 構造条件

| パターン | 成立条件 |
|---|---|
| Double Top | P1 = HH(+2) かつ P2 が Low型(符号 < 0) かつ P3 = LH(+1) かつ 5.1成立 |
| Double Bottom | P1 = LL(-2) かつ P2 が High型(符号 > 0) かつ P3 = HL(-1) かつ 5.1成立 |

P2はHL/LL(Double Top側)またはLH/HH(Double Bottom側)のどちらでもよい。

時間制限・ATR条件・出来高条件・Pivot間の最小/最大本数など、他の条件は**一切ない**。

---

## 6. Confirmed / Invalidated 判定

Candidate成立後、**毎バー**評価する。期限・バッファ・リテスト条件は**ない**。

| パターン | 状態 | 条件 | 価格系列 |
|---|---|---|---|
| Double Top | Confirmed | Low が P2(ネック)を**下方向へクロス** | Low |
| Double Top | Invalidated | High が P1(第1山)を**上方向へクロス** | High |
| Double Bottom | Confirmed | High が P2(ネック)を**上方向へクロス** | High |
| Double Bottom | Invalidated | Low が P1(第1谷)を**下方向へクロス** | Low |

### 6.1 クロスの厳密な定義

```
crossunder(x, level): x[i] <  level  AND  x[i-1] >= level
crossover (x, level): x[i] >  level  AND  x[i-1] <= level
```

### 6.2 同一バー競合

同一バーでConfirmed条件とInvalidated条件が同時成立した場合、参考元の評価順に従い
**Confirmedを優先**する。

### 6.3 判定開始タイミング

Candidateが成立した**そのバーから**判定を始める。P3成立からCandidate成立までの
間のバーへ遡って判定することはない(先読みにならない設計)。

## 7. StrategyX 共通管理仕様の適用

以下はStrategyX側の管理仕様であり、参考元のパターン判定条件を変更するもの
ではない。参考元は「最後に検出した1パターンだけを保持し、決着後も同じ水準で判定を
続ける」単一スロット方式だが、StrategyXでは全検出器共通の管理仕様に合わせる。

### 7.1 パターンごとの一意ID

```
pattern_id = パターン種類 + "_" + 全構成点のバー位置を "_" でつないだもの
```

Double Top / Bottom は構成点が3つなので:

```
pattern_id = pattern_type + "_" + P1バー + "_" + P2バー + "_" + P3バー
例: double_top_100_120_140   (P1=100本目, P2=120本目, P3=140本目)
```

構成点が1つでも異なれば別パターン。3点すべてが同一なら同じパターンとし、
何度検出処理を通っても再登録しない。

これは参考元の重複描画抑制(同じ形が毎バー再検出されるのを描画側で間引いていた
処理)を、検出器側で正しく表現したものにあたる。

**`pattern_id` は内部の重複判定だけでなく、外部出力にも必ず含める**(8章)。同一バー
で複数のパターンが決着したとき、どのイベントがどのパターンのものかを識別できる
必要があるため。

**汎用性**: 点の数を固定しないため、Head & Shoulders(5点)、Triangle、Wedge、Flag
など今後追加するパターンにも同じ規則をそのまま適用できる。Pivotを使わない
ローソク足パターンでは、構成するバー位置を同じ形で並べる。

### 7.2 Candidate成立後の構成点固定

Candidate成立時点で P1 / P2 / P3 のバー位置・価格・判定水準を固定する。以降、
新しいPivotやZigZag更新が起きても、登録済みパターンの構成点は書き換えない。

ZigZag配列の index 0 は後から置換され得るが、Candidate判定は index 1〜3 のみを
読むため、**Candidate成立時点で3点はすべて確定済み**(リペイントしない)。

### 7.3 1パターンにつき1回だけ決着

同じ`pattern_id`から Confirmed / Invalidated を複数回発生させない。一度決着した
パターンは監視を終了し、その後同じ水準を価格が何度横切っても再判定しない。

### 7.4 複数パターンの同時保持

未決着のパターンを複数同時に監視する。Pivotを共有していても、形成期間が重複して
いても、検出結果を自動削除しない。

**参考元との差異(意図的)**: 参考元は新しいパターンが出ると古いパターンの監視を
打ち切るため、StrategyX版のほうが決着イベントは多くなる。これは共通管理仕様
7.4の要求によるもので、検出条件そのものは変更していない。

### 7.5 状態遷移

```
CANDIDATE → CONFIRMED
CANDIDATE → INVALIDATED
```

参考元に期限切れ・時間切れ条件が存在しないため、**EXPIREDは使わない**
(StrategyX側で勝手に期限条件を追加しない)。

FORMING(ZigZagが育っている途中)は外部に出力しない。

### 7.6 先読み・リペイント

| 項目 | 内容 |
|---|---|
| 各構成点が確定するバー | Pivotはそのバー自身(右側確認なし) |
| Candidateを最初に認識可能なバー | P0がZigZag配列に入り、配列サイズが4以上になったバー |
| Confirmed/Invalidatedを最初に認識可能なバー | Candidate成立バー以降 |
| ZigZagが後から更新される可能性 | index 0 のみ。index 1以降は不変 |
| 参考元のリペイント挙動 | index 0 の置換のみ。Candidateは index 1〜3 を読むため影響を受けない |

バックテストでは、そのバー時点で実際に利用可能だった情報のみを使用する。

### 7.7 参考元との差異一覧(意図的なもの)

| 項目 | 参考元 | StrategyX版 | 理由 |
|---|---|---|---|
| 保持するパターン数 | 1(最新のみ) | 複数同時 | 共通管理仕様 7.4 |
| 決着後の再判定 | 続ける(同じ水準を再度横切ると再発火) | しない | 共通管理仕様 7.3 |
| 同一形状の重複検出 | 毎バー再検出(描画側で間引き) | pattern_idで1回だけ | 共通管理仕様 7.1 |
| クロス判定の水準 | Pineの`crossunder(x, series)`は前バー比較に**前バーの水準**を使う(単一スロットゆえ、パターン切替バーでは旧水準になる) | 各パターン固有の固定水準を前後バーとも使う | パターンごとに水準を固定するため(7.2)、参考元の単一スロット由来の副作用は再現しない |

## 8. 出力

**イベント一覧を正とする。** 未決着のパターンを複数同時に監視する(7.4)以上、同一
バーで2件以上のパターンが決着しうる。したがって「1バーにつき1個のBoolean」を出力の
本体にすると、イベント数も各パターンの構成点も失われる。

### 8.1 イベント一覧(欠落のない出力)

検出した全イベントを時系列順に、1イベント1レコードで並べる。同一バーに何件でも
並べられる。

| フィールド | 意味 |
|---|---|
| `pattern_id` | 7.1の一意ID |
| `pattern_type` | `double_top` / `double_bottom` |
| `status` | `candidate` / `confirmed` / `invalidated` |
| `event_bar` | そのイベントが発生したバー位置 |
| `p1_bar` / `p1_price` | 第1山(谷) |
| `p2_bar` / `p2_price` | ネック |
| `p3_bar` / `p3_price` | 第2山(谷) |
| `ratio` | 5.1で計算した値 |

同じパターンのCandidateとConfirmed(またはInvalidated)は、同じ`pattern_id`で結び付く。
1つの`pattern_id`につきCandidateが1件、決着が最大1件(7.3)。

### 8.2 Boolean系列(互換用)

StrategyXの条件式(indicatorインターフェース)がバーごとの真偽値を要求するため、
`candidate` / `confirmed` / `invalidated` の3系列も併せて返す。

| 状態名 | 意味 |
|---|---|
| `candidate` | そのバーで1件以上のパターンがCandidate成立した |
| `confirmed` | そのバーで1件以上のパターンがConfirmedになった |
| `invalidated` | そのバーで1件以上のパターンがInvalidatedになった |

**この系列は同一バーの複数イベントを1つに潰す**。件数を数えたい用途、各パターンの
構成点が要る用途(チャートへの描画など)では8.1を読むこと。
