# 形状判定版 ヘッド・アンド・ショルダーズ 仕様書

対象関数(想定): `head_and_shoulders_shape` / `inverse_head_and_shoulders_shape`
→ ラッパー `_hs_shape_state`
→ njitコア `_shape_state_core_hs`

土台: 形状判定版トリプルトップ/ボトム(`_shape_state_core3`、`docs/pattern_spec_triple_top_bottom_shape.md`)。5点構成(山1→ネック1→山2→ネック2→山3)・共通管理仕様・先読み防止の仕組みはすべて共有し、**山2(頭)の水準判定とネックラインの扱いの2点だけ**を一般的なヘッド・アンド・ショルダーズの定義に合わせて変更する。

本文は `bullish=False`(ヘッド・アンド・ショルダー・トップ=三尊天井)で記述する。`bullish=True`(逆ヘッド・アンド・ショルダーズ=逆三尊)は上下反転した鏡像。

---

## 0. トリプルSTとの違い(この2点だけ)

| # | 論点 | トリプルST | H&S(本仕様) |
|---|---|---|---|
| 1 | 山2(中央)の水準判定 | 山1・山2・山3が**全体で同水準**(3点の値幅≤tol) | **頭(山2)は肩(山1・山3)より明確に高い**ことを要求。肩1・肩3同士は同水準(tol以内)を維持 |
| 2 | ネックライン | ネック1・ネック2は近接(neck_tolerance_mult)、ブレイク判定は**水平**な水準(min/max) | ネック1・ネック2は**近接不要**(0=無制限を許可)。ブレイク判定はネック1→ネック2を結ぶ**斜めの直線を延長した値**と比較 |

それ以外(山1前点の探索、時間対称性の基準点、孤立度チェック対象、効率比・直線乖離、先読み防止、3状態モデル、パラメータの命名規則)は**トリプルSTと完全に同じ**。

## 1. 構成点と全体像

```
              頭(山2)
              /\
       肩1   /  \   肩3
       /\   /    \   /\
      /  \ /      \ /  \
   ──┘    ╲        ╲    └──── ← ブレイク(斜めネックラインを延長)
          ネック1    ネック2
```

- **肩1(山1)・肩3(山3)**: トリプルの「山1アンカー」と同じ考え方で、`|肩3 − 肩1| ≤ tol` (tol = `|肩1−ネック1|×top_tolerance_mult`)。3点まとめての値幅判定ではなく**2点だけ**の比較になる(頭は判定対象に含めない)。
- **頭(山2)**: `頭 − max(肩1,肩3) ≥ head_prominence_mult × tol_base`(新パラメータ、後述)。上限は設けない(頭がどれだけ高くても構わない)。
- **ネック1・ネック2**: トリプルのis_better(深い方優先)・窓打ち切り規則Aはそのまま流用。ただし**2ネック間の近接要求(neck_tolerance_mult)は既定で無効(0=無制限)** — 一般的なH&Sはネックラインが傾いていることの方が普通なため。

## 2. パラメータ一覧

### 2.1 トリプルSTから引き継ぐもの(意味・既定値とも同じ)

`pivot_left_bars` / `pivot_right_bars` / `prominence_atr_mult` / `pivot_spike_excess_atr_max` / `pivot_spike_window_ratio` / `max_bars_between_tops` / `symmetry_ratio_min` / `symmetry_ratio_max` / `top_tolerance_basis` / `top_tolerance_atr_mult` / `top_tolerance_mult`(肩1・肩3の同水準判定に使用) / `min_valley_depth_atr_mult` / `max_valley_depth_atr_mult` / `breakout_buffer_basis` / `breakout_buffer_atr_mult` / `breakout_buffer_mult` / `efficiency_ratio_min` / `efficiency_ratio_floor` / `trendline_dev_*` 一式 / `breakout_deadline_min_bars` / `breakout_deadline_ratio_max` / `interval_symmetry_ratio_min` / `interval_symmetry_ratio_max`(山2=頭を基準点にするのはトリプルと同じ) / `terminal_bounce_close_mult` / `breakout_type` / `neck_tolerance_mult`(意味の規約はトリプルと同じ - 2026-08-15訂正、下記2.2参照。ただし既定値はH&S側だけ0.4にチューニング済み、下記参照)。

### 2.2 新設

| パラメータ | 既定値 | 意味 |
|---|---|---|
| **`head_prominence_mult`**(新規) | **0.5** | 頭が肩の高い方よりどれだけ高くなければならないかの倍率。基準幅は`top_tolerance_mult`と同じ`base_leg = \|肩1−ネック1\|`を共有。`head − max(肩1,肩3) ≥ head_prominence_mult × base_leg`を要求 |

`neck_tolerance_mult`の既定値は2026-08-15にユーザー判断で**0.25→0.4**へ調整した(トリプルは0.25のまま、H&Sだけ変更)。USDJPY 15分足・全期間・ショートのバックテストで比較したところ、0.25→0.4で取引数45→64件、PF1.59→1.58(ほぼ不変)、純利益137→183pips、Recovery Factor1.67→2.14と、質を落とさず件数だけ増える結果だった。さらに詳しく調べると、0.4で新たに拾えた19件はいずれもネック1・ネック2の実際の乖離比率が0.083〜0.214(0.25の基準を元々満たす水準)で、"ネックが離れているから緩さが必要だった"パターンは1件も無かった — 探索(is_better・窓打ち切り規則Aによる逐次的なネック確定)が、0.25では届かない位置に本来なら基準を満たすはずの候補を取りこぼしていた(トリプルSTの「なぜ7件検出されなくなったか」調査と同根の現象)。0.75を超えたあたりから初めて本当に乖離比率0.25超のパターンが混ざり始め、PF・Recoveryも明確に悪化する。0.4はこの副作用を実用的に緩和する値として選んだもので、「教科書的な形の基準を緩めた」わけではない。

`neck_tolerance_mult`(既定0.25)は当初「H&Sはネックラインの傾きを許容するため既定で無効(0=無制限)」としていたが、2026-08-15にユーザー判断で撤回・訂正した。トリプルと同じ規約(`0`は**完全な同水準**を意味するリテラルな許容誤差、無制限にする手段自体を提供しない)に統一し、既定値も0.25にそろえた。傾いたネックラインは、ネック1・ネック2がこの許容誤差の範囲内でズレることによって(必要なら`neck_tolerance_mult`を大きくすることによって)表現する。

## 3. 検出アルゴリズムの変更点

トリプルSTの①〜⑫のうち、変わるのは⑤⑥(山2候補の判定)と⑪(ブレイク判定水準)のみ。

### 3.1 頭(山2)候補の探索(⑤⑥の変更)

トリプルは「tol以内で最高値」だったが、H&Sでは以下に変更する:

```
window2内の両側確認ピボットのうち、
  breach2: 肩1の水準を「下回りすぎる」(肩1 - tol より安い)ものが出たら窓破綻(トリプルと同じ、下方向のみ)
  候補条件: 特に上限なし(頭はいくら高くてもよい)
  正準化: 窓内で最も高い1本(「より極端な値のときだけ更新」、トリプルの山2と同じ更新規則)
→ head_true_bar / head_price

その後、
  head_price - max(肩1_price, 肩3_price候補が決まった時点) ≥ head_prominence_mult × base_leg
を満たさなければ候補ごと不成立(肩3が決まった直後、⑦の深さ判定と同じタイミングでチェックする - 肩3が決まるまでは「肩の高い方」が確定しないため)。
```

### 3.2 ネックライン(⑪の変更)

トリプルは`neck_price = min(ネック1,ネック2)`という**固定の水準**を使っていたが、H&Sは**ネック1→ネック2を結ぶ直線を延長した、判定バーごとに変わる水準**を使う。

```
neckline_at(j) = ネック1_price + (ネック2_price - ネック1_price) × (j - ネック1_bar) / (ネック2_bar - ネック1_bar)

confirm_j: 終値/ヒゲ が neckline_at(j) − buf_j を下抜け(bullishは上抜け)
fail_j   : 終値/ヒゲ が 頭_price + buf_j を上抜け(bullishは下抜け、worse_extremeは頭で確定- 頭が3点中最高値であることは構造上保証済み)
```

`buf_j`(ブレイク判定余白)の深さ計算(`depth`)は、トリプルの「neck_ref側の谷深さ」に代えて、**ネック1側・ネック2側どちらか深い方**(肩の水準からの絶対値が大きい方)を使う。事前undercut・山1前点の探索(⑧)は**ネック1固定**のままなので変更なし。

### 3.3 なぜこの2点だけの変更で十分か

- 肩1・肩3の同水準判定、時間対称性、効率比・直線乖離、孤立度チェック、窓打ち切り規則、先読み防止(confirm_floor)は「頭が特別に高い」「ネックラインが傾く」という2点と無関係に成立する仕組みなので、トリプルの実装をそのまま流用できる。
- ネック1・ネック2の**探索**(is_better・規則A)自体は変更不要 — 変わるのは探索方法ではなく、探索後に「2つのネックをどう使ってブレイクを判定するか」だけ。

## 5. 実装時の検証手順

1. 合成データ(左肩・頭・右肩が明確に高さの違う5点)でCandidate/Confirmedが出ることを確認。
2. `head_prominence_mult`を0にすると、事実上トリプルSTと同じ判定に近づく(頭の高さ制約が外れる)ことを確認 — ただしネックライン延長の計算式が違う点は残る。
3. `neck_tolerance_mult`を大きくすると、傾きの急なネックラインが弾かれることを確認。
4. 実データ(USDJPY 15分足)で検出件数・実行速度を確認。
